# Backlog

Tasks flow: `proposed -> briefed -> designed -> in progress -> testing ->
code review -> security review -> accepted`. Only the Producer edits statuses; a
task is "accepted" only with a Tester PASS, a Code Reviewer pass, and Product
Owner acceptance on record.

Every task, once designed, records two things: its **owner** (junior-developer,
developer, senior-developer, or principal-developer, assigned by the Architect)
and its **verification method** (the Tester's "how will I know this works": run
X, expect Y).

Group tasks under one `### Project: <slug>` heading per project, so a single
project's rows can be pulled with grep instead of reading the whole file.
